title: Confirm a PaymentIntent (create the operator invoice)
description: |
  Chooses an operator, creates the payment (invoice) at that operator,
  records a pending Charge and moves the intent from
  `requires_payment_method` to `requires_action`. Show the buyer the
  returned `next_action` (QR code, bank-app links or a redirect).
  Payment completes asynchronously: the intent becomes `succeeded` and
  a `payment_intent.succeeded` event is sent.

  **Skip this call when you use hosted checkout** — the hosted page
  confirms the intent itself.

  **Operator choice**, in order: the `operator` you send → automatic
  routing among the project's enabled operators (when
  `automatic_operator` is true) → the first entry of
  `allowed_operators`. The operator must have an active connection and
  be switched on for this project.

  **Errors** (besides the common ones):
  - `404 resource_missing` — no such intent in this project.
  - `400 payment_intent_unexpected_state` — the intent is not in
    `requires_payment_method` (already confirmed, paid, canceled, or a
    concurrent confirm won). Re-read the intent.
  - `400 operator_not_allowed` (`operator`) — the operator is not in
    `allowed_operators`; no eligible operator was found; the operator
    has no active connection or is not switched on for this project.
  - `400 operator_unknown` (`operator`) — the operator id is not known
    to this API.
  - `402` (`type: payment_method_error`) — the operator declined; `code`
    is the operator's reason.
  - `424` (`type: operator_error`) — the operator failed or timed out
    (`operator_timeout`). Safe to retry with the same `Idempotency-Key`.
  - `403 connector_required` / `403 settlement_account_required`.

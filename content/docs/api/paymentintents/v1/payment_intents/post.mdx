title: Create a PaymentIntent
description: |
  Creates a PaymentIntent for the amount you want to collect. The new
  intent is in status `requires_payment_method` — the normal "waiting
  for the buyer" state, not an error.

  **Which operators can be used.** By default (`automatic_operator:
  true`, no `allowed_operators`) every operator switched on for the
  key's project is eligible and Wire routes to the best one. Send
  `allowed_operators` only to narrow that set.

  **Next step.** Either create a checkout session for the intent (hosted
  page — recommended) or call `/v1/payment_intents/{id}/confirm`
  yourself. Do not do both. By default an intent expires **10 minutes**
  after creation (`expires_at`); an expired, unpaid intent is canceled
  automatically.

  **Errors** (besides the common ones):
  - `400 parameter_missing` (`amount`) — `amount` omitted.
  - `400 amount_too_small` (`amount`) — `amount` is ≤ 0.
  - `400 amount_too_large` (`amount`) — `amount` is above
    1,000,000,000.
  - `400 currency_unsupported` — `currency` is not `MNT`.
  - `400 parameter_invalid` (`description`) — longer than 500 bytes.
  - `400 operator_unknown` (param `allowed_operators[i]`, the message
    names the offending value) — an `allowed_operators` entry is not an
    operator id available on this API, or the list has more than 10
    entries. Fix: omit `allowed_operators`, or use only the operator ids
    shown on your dashboard's Connectors page.
  - `400 metadata_invalid` — over 50 keys, an empty key, a key over
    40 characters or a value over 500 characters.
  - `403 connector_required` / `403 settlement_account_required`.
